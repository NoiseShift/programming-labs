## 2. Краткие теоретические сведения

* **Git** — это распределенная система контроля версий (VCS). Она отслеживает изменения в файлах проекта, позволяет делать «снимки» текущего состояния (коммиты), возвращаться к истории версий и вести параллельную разработку без риска потери данных.
* **Локальный репозиторий** — служебный каталог `.git` на компьютере пользователя, в котором хранится база данных изменений, история коммитов, ветки и конфигурация проекта.
* **Удаленный репозиторий** — копия локального проекта, размещенная на внешнем сервере (хостинге репозиториев, например, GitHub). Служит для резервного копирования, командной работы и публикации исходного кода.
* **Индекс (Staging Area)** — промежуточная область подготовки изменений перед их фиксацией. Команда `git add` добавляет файлы в индекс.
* **Коммит (Commit)** — зафиксированное и сохраненное состояние отслеживаемых файлов с уникальным SHA-хешем. Каждый коммит сопровождается метаданными: автор, дата и осмысленное сообщение (`commit message`).
* **Ветка по умолчанию (`main` / `master`)** — основная линия разработки репозитория.

## 5. Ответы на контрольные вопросы

1. **В чем разница между локальным репозиторием Git и удаленным репозиторием GitHub?**  
   *Локальный репозиторий* находится на локальном диске пользователя (в скрытом каталоге `.git`) и позволяет работать автономно без интернета (создавать коммиты, переключать ветки, смотреть историю). *Удаленный репозиторий* (например, на GitHub) размещен в облачной инфраструктуре и служит центральным узлом для резервного копирования, демонстрации исходного кода и совместной командной работы.

2. **За что отвечают команды `git add` и `git commit`? Какова последовательность их применения?**  
   * `git add` переносит измененные или новые файлы в область подготовки (индекс / staging area).
   * `git commit` создает постоянный снимок (snapshot) всех подготовленных в индексе изменений и записывает его в историю проекта с комментарием.  
   *Последовательность:* сначала выполняется `git add <путь_к_файлу>` (подготовка), затем `git commit -m "описание"` (фиксация).

3. **Что делает команда `git push`?**  
   Команда `git push` передает зафиксированные локальные коммиты и изменения веток из локального репозитория в удаленный (например, на GitHub). Параметр `-u` (`--set-upstream`) при первом запуске связывает локальную ветку с веткой удаленного репозитория по умолчанию.

4. **Зачем нужна команда `git status`?**  
   Она отображает текущее состояние рабочей директории и индекса: показывает, какие файлы были изменены, какие добавлены в staging area (`staged`), какие еще не отслеживаются (`untracked`), а также информирует о текущей ветке и ее синхронизации с удаленным репозиторием.
